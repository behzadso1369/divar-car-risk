# ریسک‌سنج آگهی خودرو دیوار

لینک آگهی دیوار را می‌گیرد و می‌گوید این خودرو **ریسک پایین / متوسط / بالا** دارد، چرا، قیمتش منصفانه است یا نه، و خریدار چه سؤال‌هایی باید از فروشنده بپرسد.

همه‌چیز **رایگان و محلی** است: بدون هیچ مدل پولی یا API پولی. یادگیری ماشین با scikit-learn، بینایی ماشین با OpenCV.

## اجرا

```bat
run.bat
```
یا دستی:
```bash
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python cli.py serve --port 8000
```
سپس `http://127.0.0.1:8000` را باز کنید.

### خط فرمان
```bash
# بودجه به میلیون تومان
.venv\Scripts\python cli.py analyze "https://divar.ir/v/.../ga_i3H7H" --budget-max 1500 --usage city --priorities resale,low_maintenance --images --open

# ثبت نتیجه کارشناسی حضوری (داده آموزشی)
.venv\Scripts\python cli.py label ga_i3H7H --hidden-issue yes --severity 2 --notes "گلگیر عقب هم رنگ داشت"

# آموزش مدل‌ها
.venv\Scripts\python cli.py train

# تست‌ها
.venv\Scripts\python -m unittest discover tests
```

### API
```
POST /api/analyze
{"url": "https://divar.ir/v/...", "needs": {"budget_max": 1500000000, "usage": "city"}, "images": false}
```

## صداقت فروشنده (اول گزارش)
فایل: `app/honesty.py` — جدا از ریسک خودرو می‌سنجد **چقدر می‌شود به حرف‌های آگهی اعتماد کرد**.

هر ادعای متن (بدون رنگ، فنی سالم، دست اول، خانمی، در حد صفر، بیمه ۱۲ ماه، ...) استخراج می‌شود و یکی از این وضعیت‌ها را می‌گیرد:

| | وضعیت | یعنی |
|---|---|---|
| ✅ | سازگار | با فرم، فیلدها و قیمت همین آگهی جور است |
| ❌ | متناقض | با اطلاعات دیگر همین آگهی تناقض دارد |
| ⚠️ | بعید | با سن، کارکرد، قیمت یا نوع فروشنده جور نیست («در حد صفر» برای ۱۵ ساله) |
| ❔ | غیرقابل بررسی | فقط حرف است → یک سؤال برای تبدیل آن به ادعای قابل بررسی ساخته می‌شود |

امتیاز ۰ تا ۱۰۰ از چهار شاخص: **سازگاری** (۳۵٪)، **باورپذیری** (۲۵٪)، **جزئیات مشخص در برابر تعریف کلی** (۲۰٪)، **شفافیت** (۲۰٪؛ اعتراف به ایراد +، اجازه کارشناسی +، «کارشناسی نمی‌دم» −).
قواعد مهم: آگهی دارای تناقض حداکثر ۷۴ می‌گیرد؛ «همه‌چیز عالی + خیلی ارزان» و قیمت طعمه به‌شدت امتیاز را کم می‌کنند.

**یادگیری:** بعد از کارشناسی، پایین صفحه گزارش برای هر ادعا «درست بود / نادرست بود» را ثبت کنید (یا `cli.py label <توکن> --hidden-issue no --claims body_no_paint=false,engine_ok=true`).
- از ۵ نمونه به بالا: نرخ نادرستی هر نوع ادعا در گزارش‌ها و صفحه «آمار ادعاها» (`/insights`) نشان داده می‌شود.
- از ۱۰۰ نمونه به بالا: `cli.py train` مدل ML «احتمال نادرست بودن ادعا» (`app/ml/claim_model.py`) را آموزش می‌دهد.

## مراحل تحلیل

| مرحله | فایل | کار |
|---|---|---|
| ۱. نیاز مشتری | `app/stage1_needs.py` | بودجه، نوع استفاده، گیربکس، کارکرد، اولویت‌ها، ریسک‌پذیری → درصد تطابق + پیشنهاد مدل |
| ۲. استخراج و دروغ‌سنجی متن | `app/stage2_text.py` + `app/lexicon.py` | استخراج قطعات آسیب‌دیده از متن فارسی و **مقایسه با فرم ارزیابی فروشنده**؛ تناقض کارکرد/سال؛ سند، فشار فروش، کلمات طفره |
| ۳. قیمت‌گذاری اختصاصی | `app/stage3_pricing.py` | جمع‌آوری آگهی‌های هم‌مدل و هم‌سال، حذف داده پرت، **رگرسیون Huber** روی کارکرد، تعدیل بابت خسارت → قیمت منصفانه |
| ۴. رفتار آگهی | `app/stage4_behavior.py` | تعداد عکس، نمایشگاه/مالک، طول توضیحات، عمر آگهی، نردبان، کاهش قیمت، متن تکراری |
| ۵. تحلیل عکس (اختیاری) | `app/stage5_images.py` | نور کم، تاری، عکس تکراری (perceptual hash)، وضوح |
| ۶. رتبه‌بندی نهایی | `app/stage6_scoring.py` | جمع امتیازها با سقف هر مرحله، سطح‌بندی، اطمینان تحلیل، توصیه، سؤال‌ها |
| ۷. دانش اختصاصی مدل | `data/knowledge/car_models.json` | ایرادات رایج، چک‌لیست بازدید، ریسک ذاتی و امتیاز هر مدل |

### دروغ‌سنجی چطور کار می‌کند؟
فروشنده در دیوار سه جا اطلاعات می‌دهد: **متن آزاد**، **فرم ارزیابی** (موتور/شاسی/بدنه/گیربکس + قطعات) و **فیلدها** (کارکرد، سال). سیستم این سه را با هم مقایسه می‌کند. مثال واقعی (آگهی `ga_i3H7H`):

- فرم: «رنگ‌شدگی در ۱ ناحیه: درب سمت راننده جلو»
- متن: «درب راننده تعویض، گلگیر راننده تعویض»
- نتیجه: دو تناقض (نوع خسارت درب + گلگیر اعلام‌نشده) و دو سؤال مشخص برای فروشنده.

## یادگیری ماشین

| مدل | داده | کی فعال می‌شود |
|---|---|---|
| رگرسیون قیمت محلی (Huber) | آگهی‌های مشابه همان لحظه | همیشه |
| مدل سراسری قیمت (Gradient Boosting) | همه آگهی‌های جمع‌شده در دیتابیس (۳۰ روز اخیر) | بعد از `train`، فقط وقتی آگهی مشابه کافی نباشد |
| **مدل ریسک** (TF-IDF متن + ویژگی‌های عددی → Logistic Regression) | **نتیجه کارشناسی‌های حضوری شما** | بعد از ثبت حداقل ۳۰ نتیجه و `train` |

**مزیت رقابتی اصلی شما مدل ریسک است:** هر بار که خودرویی را کارشناسی می‌کنید، نتیجه را ثبت کنید (در صفحه گزارش یا با `cli.py label`). مدل یاد می‌گیرد کدام نشانه‌ها واقعاً به ایراد پنهان ختم می‌شوند و وزن‌ها را از داده واقعی تنظیم می‌کند. بعد از آموزش، امتیاز نهایی ترکیب امتیاز قاعده‌محور (۶۰٪) و مدل (۴۰٪) است؛ نسبت در `app/config.py` قابل تغییر است.

## بهبود دقت (کار شما)
- **`app/lexicon.py`**: الگوهای فارسی را از تجربه کارشناس‌ها کامل کنید. بعد از هر تغییر `python -m unittest discover tests` بزنید.
- **`data/knowledge/car_models.json`**: ایرادات رایج و چک‌لیست هر مدل را کامل و اصلاح کنید.
- **`app/config.py`**: ضرایب تخفیف خسارت، آستانه‌های سطح ریسک و سقف هر مرحله.

## محدودیت‌ها (صادقانه)
- تحلیل متن قاعده‌محور است؛ غلط املایی شدید («متور» به‌جای «موتور») یا جمله‌بندی خیلی غیرمعمول ممکن است تشخیص داده نشود.
- آگهی‌های مشابه وضعیت بدنه ندارند، پس قیمت منصفانه تقریبی است. مدل سراسری قیمت در تست حدود ۲۶٪ خطای میانگین داشت و فقط پشتیبان است.
- تحلیل عکس فعلی فقط کیفیت عکس را می‌سنجد، نه اختلاف رنگ پنل‌ها. برای آن، نسخه بعد باید یک مدل بینایی (مثلاً YOLO) روی عکس‌های برچسب‌خورده خودتان آموزش ببیند.
- از API عمومی وب‌سایت دیوار استفاده می‌شود (با فاصله ۱ ثانیه بین درخواست‌ها و کش). برای استفاده تجاری در مقیاس بالا، شرایط استفاده دیوار و پلتفرم رسمی توسعه‌دهندگان (کنار دیوار) را بررسی کنید.
- خروجی «ریسک برآوردی بر اساس اطلاعات آگهی» است و جایگزین کارشناسی حضوری نیست.
